全部是 **free 授權**，用機構的 Adobe 帳號授權後下載。

**這裡只記錄「怎麼做出來的」，不放素材本身** — 授權影片不適合進版控，
而且照下面的步驟可以在幾分鐘內完整重建。

## 轉向：綜藝比手畫腳

做到一半改了設計方向 —— 不再要求「照服員正確示範該動作」，改成綜藝節目那種
誇張比手畫腳。這個轉向解掉了先前卡死的題目，因為**謎底從「場景」搬到「手勢」**。

先前卡住的 11 到府服務、14 準時上工、12 和芮居家，都是因為謎底綁在台灣特定場景
（樓梯間鐵門、騎樓機車），而素材庫沒有台灣民宅。改走手勢路線後場景就不重要了 ——
誇張的動作自己會說話，在哪拍的沒人在意。

Q16 就是照這個邏輯做的：素材是一位上班族在辦公室手舞足蹈，不是照服員、
也不是台灣辦公室，但「終於解脫」那個情緒一看就懂。

## 重建步驟

```bash
# 1. 授權並下載（Adobe MCP: asset_license_and_download_stock）
#    回傳的 S3 presigned URL 有效期 1 小時
curl -sSL -o stock/<ID>.mov "<presigned-url>"
```

```bash
# 2. 裁成直式 9:16。素材都是 16:9，直接裁會切掉人，
#    所以主畫面等比縮放置中、上下用放大模糊的同一畫面填滿。
FILTER='[0:v]crop=W:H:X:0[c];[c]split=2[bg][fg];
[bg]scale=1080:1920:force_original_aspect_ratio=increase,crop=1080:1920,gblur=sigma=42,eq=brightness=-0.08[bgb];
[fg]scale=1080:-2:flags=lanczos[fgs];
[bgb][fgs]overlay=(W-w)/2:(H-h)/2[v]'

ffmpeg -ss <SS> -t <T> -i stock/<ID>.mov -filter_complex "$FILTER" -map "[v]" \
  -c:v libx264 -profile:v high -level 4.0 -pix_fmt yuv420p -crf 20 \
  -movflags +faststart -an "out/Q<NN>_<答案>.mp4"
```

`-map "[v]"` 是必要的 — 來源 .mov 帶一條 data stream，不指定就會被一起複製進去。
`-an` 確保沒有音軌。

### Q12 和芮居家（壓軸，唯一的剪接題）

題庫本來就把這題設計成三段式（和 → 居家 → 比愛心）。壓成兩拍：

| 段 | ID | `-ss` | `-t` | crop | 內容 |
|---|---|---|---|---|---|
| A | 404495187 | 4.0 | 7.5 | `2000:2160:920:0` | 照服員手扶阿嬤肩膀，阿嬤笑著回應（和＋居家）|
| B | 525277204 | 1.6 | 4.5 | `2000:2160:920:0` | 雙手比愛心（收尾）|

兩段用同一組 crop 參數與 `-r 25`，主畫面大小一致，接起來才不會跳。
先各自輸出成 `segA.mp4`／`segB.mp4`，再用 concat demuxer 硬接：

```bash
printf "file 'segA.mp4'\nfile 'segB.mp4'\n" > concat.txt
ffmpeg -f concat -safe 0 -i concat.txt -c:v libx264 -pix_fmt yuv420p \
  -crf 20 -movflags +faststart -an "out/Q12_和芮居家.mp4"
```

**A 段的阿嬤跟 Q06 是同一位、同一個攝影棚**（同一個素材系列）。壓軸出現看過的臉是加分，
不是問題 —— 但主持人要知道，免得有人以為題目重複。

Q14 一開始裁成滿版 9:16（`1215:2160:1620:0`），結果變成人像特寫、手錶被擠到邊緣。
**手錶就是謎底**，所以改用較寬的裁切加模糊帶，讓「低頭看錶」這個動作完整入鏡。
取捨：主畫面變小，但謎題成立。

Q16 從 4.4s 開始是為了避開前段的筆電畫面與桌上文件 —— 那些帶字。
後段她離開座位跳舞，畫面裡只剩人和空白便利貼。

**Q10 是例外** — 人物夠居中，可以直接裁滿版 9:16，不需要模糊帶，畫質最好：

```bash
ffmpeg -ss 1.5 -t 12.0 -i stock/455120904.mov \
  -vf "crop=1215:2160:1236:0,scale=1080:1920:flags=lanczos" \
  -map 0:v:0 -write_tmcd 0 \
  -c:v libx264 -profile:v high -level 4.0 -pix_fmt yuv420p -crf 20 \
  -movflags +faststart -an "out/Q10_陪伴散步.mp4"
```

`-write_tmcd 0` 是必要的 — 來源帶 timecode 軌，不關掉會被寫進 mp4 變成一條 data stream。
用 `filter_complex` 的那幾題不會有這個問題（濾鏡輸出等於重建了串流）。

## 已否決的素材

**499563095** — 標題寫 "Asian caregiver helping senior male from falling"，
實際內容是阿公全程癱在地上、照服員跪著急救。那是「跌倒受傷」不是「預防跌倒」，
而且遊覽車上玩遊戲放老人倒地，氣氛不對。已捨棄。

**教訓：素材庫標題會灌水，每一支都要下載看過才算數。**
縮圖 CDN（`t3/t4.ftcdn.net`）被這個執行環境的網路政策擋住，
Adobe 的 `asset_inline_preview` 端點也回 400，所以沒有便宜的預覽方式 —
一支就是 350MB 的完整下載。挑素材要保守。

## Q13 服務紀錄 — 放棄的理由

找過四輪，兩個獨立的原因讓這題在素材庫走不通：

1. **沒有對應素材**。亞洲居家照顧的「填服務紀錄」情境不存在。搜尋結果一律漂移成
   「照服員跟長輩聊天」或「商務人士簽文件」。
2. **更根本的：這題的動作本身就會帶字**。紀錄表、平板畫面、簽名文件 —— 所有
   「在記錄」的實拍鏡頭都是文件特寫，紙上或螢幕上必然有字。這直接違反
   「畫面上不可出現任何文字」，而題庫自己在這題的提示詞也寫了
   「畫面與螢幕上都不要出現任何文字」。

唯一乾淨的素材是「手在**空白**筆記本上寫字」的特寫，但那只讀得出「寫字」，
讀不出「服務紀錄」，當謎題無效。

**沒有出片，而不是出一支帶字的。** 這題若要做，只有兩條路：自己拍（把紀錄表翻面
或只拍打勾的手勢），或用動畫版（文字可以完全控制）。

### 一則修正

先前這一節列了「素材庫做不出來」的題目，把 12、14、16 都算在內，理由是它們綁死台灣場景
（公寓樓梯間、騎樓機車、台灣辦公室）。**改走比手畫腳之後這個判斷就不成立了** ——
謎底一旦搬到手勢上，場景就不重要，三題全部做出來了。
